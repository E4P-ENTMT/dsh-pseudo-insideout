# dsh-pseudo-insideout 可视化控制台设计

[文档导航](README.md) · [当前交付状态](08-delivery-report.md)

> 本文中的 1.0–1.2 为历史开发阶段编号；当前包版本为 `0.0.1`。验收结果仅适用于记录中注明的工件与执行范围。

阶段：瀑布模型 / 详细设计。实现必须遵循主设计与冻结 API；本文不代替宿主插件协议。

## 1. 界面目标与约束

- 为真实 DSH 插件提供可操作的本地可视化控制台，不使用虚构数据掩盖运行状态。
- 日常召回仅使用活跃库。封存库独立浏览，页面查阅不等于注入上下文，临时调阅不等于恢复活跃。
- 不以衰减、后台整理、容量限制或低相关性触发删除；每个记忆操作均提供可核对结果。
- 中文界面，键盘可操作、焦点可见、移动端可用。任何含义都不能仅通过颜色表达。
- 原始经历与后续解释分开显示；失效版本、来源、时间、状态变更和操作历史可追溯。
- 运行能力按实际宿主状态显示：已连接、等待宿主、暂停写入、失败。仅显示经后端确认的成功。

## 2. 信息架构

### 总部

顶部显示插件名称、运行连接状态、数据更新时间及刷新操作。指标显示活跃记忆、封存记忆、核心记忆、待审建议。主区域包含实际记忆球图、情绪强度条、当前会话/回合的召回记录和近期活动。空系统显示明确的首次使用入口，不注入演示数据。

记忆球大小对应重要度，文字标签表示事件类别，色环对应情绪。球可点击打开记忆详情。背景装饰不承载数据含义。

### 记忆大厅

活跃记忆的可搜索列表和球体视图。筛选至少包含搜索文字与类别；每条显示标题、日期、类型、重要度、情绪、来源及当前状态。新建记忆使用独立表单，明确原文和来源。编辑生成修订，不静默覆盖原文。可封存并填写原因。

### 封存档案馆

始终显示“此库不参与日常召回”。独立查询 archive scope，显示封存时间和原因。操作分为：

1. 查看：读取详情，仅供控制台展示。
2. 临时调阅：提交独立操作，选择目标会话；成功后展示授权及有效期，不在该响应中返回正文，并保持封存状态。
3. 恢复活跃：清楚说明今后可参与日常召回，执行后更新两库计数。

### 人格岛

以图节点展示实际人格岛及其支持记忆，并提供对应的可访问列表及独立核心记忆区域。支持记忆不要求先成为核心记忆。每座岛显示名称、描述/倾向、支持记忆和更新时间；无证据时显示“尚无支持记忆”。人格变化仅通过已审批的建议或显式编辑操作生效。

### 梦工坊

展示后台整理运行状态与建议队列。建议卡包含类型、标题、理由、证据记忆、预期变更和状态。批准/拒绝使用明确按钮，禁止仅点击卡片即应用。手动触发整理后显示真实结果或错误。原文内容完整保留。

### 运行与设置

日志按时间显示读取、写入、纠错、封存、恢复、临时调阅、建议审批和运行异常。配置编辑只覆盖实际受支持字段；硬性“禁止自动删除”作为只读规则显示。配置保存前后均以服务器返回为准。

## 3. 统一交互

- 侧栏导航在宽屏固定，在窄屏转为横向标签。当前页用文字/图标/色块共同区分。
- 全局通知仅报告已确认的操作，失败显示可读原因，保留用户输入供重试。
- 请求期间相关提交按钮禁用，避免重复提交；页面空态、加载态、错误态彼此区分。
- 记忆详情用侧边抽屉或模态对话框，显示 ID、原文、来源、解释、版本、状态与可执行动作。
- 模态支持 Escape、关闭按钮、点击遮罩关闭，恢复打开前焦点，并限制焦点在打开的模态内。
- 编辑与新建表单验证必填项并使用内联错误；保存成功才关闭。
- 安全渲染外部内容，全部文本按文本节点插入，禁止将记忆原文直接设为 HTML。
- 对删除不设置日常快捷按钮。若总设计保留显式永久删除，必须单独分区且明确识别目标。

## 4. 视觉规范

- 风格：参考 Inside Out 的蓝紫色总部、暖白正文与发光记忆球；金色用于主要操作和核心记忆，蓝/紫/青用于分类强调，绿色专用于成功状态。六维情绪各用明确颜色并保留文字标签，见 [1.0.1 配色参考](09-insideout-palette.md)。
- 排版：系统无衬线字体，标题有层级，元信息采用等宽字体；紧凑但保留阅读间距。
- 数据组件：记忆球/节点图、指标、情绪水平条、时间线；每个图形提供可读文本替代。
- 动效：限于状态切换、微弱入场；尊重 prefers-reduced-motion；无持续转动和强制镜头运动。
- 响应式：≥1100px 侧栏加双列总部；700–1099px 单列主体；<700px 横向导航、堆叠表单与卡片。

## 5. 已冻结的 API 依赖

实现严格遵循 [接口与数据契约 v1](03-contracts.md)。基础路径 `/api/pseudo-insideout/v1`。静态 HTML 的 `__INSIDEOUT_BOOT__` 由宿主注入 `{apiBase,token,mode}`；所有 API 请求携带 `X-InsideOut-Token`。前端只通过集中适配器访问。

宿主范围扩展：首次 `/state` 读取当前范围，之后使用 `runtime.scopeId` 在所有请求中附带 `X-InsideOut-Scope`。控制台以 `state.scopes:[{id,label,workspaceId,agentId}]` 提供选择器。切换范围关闭旧模态、清空旧筛选/视图数据、增加请求代次，任何旧请求的结果都不渲染到新范围。可见范围枚举为 `session/workspace`，workspace 表示当前工作区及 Agent 范围。临时调阅会话仅来自当前 scope 的 `state.sessions`，会话私有记忆进一步限制为来源会话。

完整性扩展：记忆大厅与档案馆使用 `offset` 分页，每页 50 条，筛选和范围切换回到首页；响应 `{items,total,offset,limit}`。人格岛核心记忆使用独立 `core=true` 查询并分页，不从普通列表截取。`state.storage.issues` 显示明确的数据问题与相关 ID，同时保留其他可用内容。梦工坊 `conflict` 建议的批准只代表人工已阅，不自动判断真值或改写记录；界面采用“标记已核对”，与其他批准变更区分。

| 用途 | 建议接口 | 核心语义 |
|---|---|---|
| 初始化/刷新 | GET /state | runtime、情绪、统计、核心记忆、人格岛、最近召回 |
| 浏览库 | GET /memories?tier=active\|archive&q=... | tier 必须显式，服务端执行分库查询 |
| 新建 | POST /memories | 原文、标题、来源、类别、重要度 |
| 详情 | GET /memories/:id?tier=active\|archive | 原始内容、当前版本、版本记录、关联、生命周期 |
| 修订 | PATCH /memories/:id | expectedVersion 与 reason；产生可追溯修订 |
| 封存 | POST /memories/:id/archive | expectedVersion 与 reason，独立迁移，不删除 |
| 恢复 | POST /memories/:id/restore | expectedVersion；重新加入活跃召回 |
| 临时调阅 | POST /memories/:id/recall | sessionId 从真实 state.sessions 选择；一次 turn 消费、10分钟有效，返回授权不含正文 |
| 新理解 | POST /memories/:id/interpretations | expectedVersion、text、evidenceIds；保留原文 |
| 明确删除 | DELETE /memories/:id | expectedVersion 与完整 ID confirmation；说明宿主历史和外部备份不由插件删除 |
| 整理与建议 | GET /dreams 与 POST /dreams/run | 列表与手动启动 |
| 审批 | POST /dreams/:id/approve\|reject | expectedVersion；明确应用或拒绝，不修改原始经历 |
| 人格岛 | GET /islands 与 PATCH /islands/:id | expectedVersion；编辑标题、描述、启用状态 |
| 运行记录 | GET /logs | 可读动作、目标、结果和时间 |
| 配置 | GET/PATCH /config | 支持字段及硬规则 |

API 返回稳定 ID 和 ISO 时间。错误为 `{ error: { message, code, details? } }`，集合为 `{items,total?}`。缺少宿主连接时显示“未连接 DSH 会话”；独立运行与 DSH 连接状态分别呈现。已进入宿主会话历史的内容无法由本插件保证抹除，临时调阅与删除界面均提示该限制。配置只提交契约字段，禁止自动删除是只读硬规则。

## 6. 验收条件

1. 全新数据目录打开全部页面无脚本错误，空态与宿主状态准确。
2. 新建记忆后在活跃库可见，详情含原文和来源；纠错后可看到前后版本。
3. 封存后活跃库不再返回该记录，档案馆可见且记录原因。
4. 档案查阅不改变生命周期；临时调阅与恢复活跃的调用和结果不同。
5. 梦工坊建议只有批准后才产生影响，拒绝保留决策记录。
6. 核心记忆/人格岛与情绪视图均来自真实响应，没有演示数据。
7. 网络错误、失败保存、空结果、慢请求均有明确反馈。
8. 表单键盘流程、模态焦点、窄屏布局与减少动效设置可用。
9. 记忆内容中的 HTML/脚本按普通文本展示。
10. 所有存储与控制台行为遵守自动操作不删除原始记忆的硬规则。

## 7. 1.1 成长与管理交互

总部增加会话工作台：目标、关注点、精力及固定工作记忆，保存使用版本检查。六维情绪可重置。记忆大厅增加按日期的球体/列表视图、混色情绪、日期/人物/情绪过滤与批量选择；批量封存/恢复保持单次事务。详情显示信息归属、自动提炼依据与显式读取的旧提炼历史。

档案馆区分普通封存和回收箱。移入回收箱可恢复，不自动清空；回收箱内另行填写完整 ID 永久删除。人格岛有可读节点图、证据链接和成长时间线，逐项显示修改前后并支持回退。封存人格版本通过独立按钮读取；全部未修订来源恢复后才能恢复旧解释，恢复后保持停用。

运行页增加按轮回应依据：实际进入上下文的状态、选中和未选中原因、宿主返回的辅助调用 token 与状态。没有回执时显示未提供，不估算费用。设置提供语义开关、关怀间隔和时区；安静时段抑制定时整理与跟进建议；对话完成或手工整理仍可生成普通建议。相关API见 [1.1 契约](03-contracts.md)，实际交互验收见 [UI记录](ui-validation.md)。

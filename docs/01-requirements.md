## 1. 产品目标与交付边界

交付可由 DSH 加载、安装、启停的本地插件 `dsh-pseudo-insideout`，不是一个仅能单独运行的网站。插件以《头脑特工队》中的记忆、情绪和人格岛作为交互比喻，组织 agent 的经历和状态，并提供可视化控制台。产品不声称拥有真实情绪、意识或心理诊断能力。

本次交付覆盖需求、总体设计、详细设计、实现、验证及交付说明。各阶段形成可审查工件；进入下一阶段前记录基线。后续发现问题可以回改前一阶段，同时更新关联需求和测试，不能靠跳过验证来维持表面的顺序。

部署范围为单机、一个工作区内的单 agent 数据库。不同 agent 或工作区必须使用不同数据根。支持同一数据根中的多个会话标识；不提供云同步、多用户协作、分布式数据库、跨设备一致性，也不自动购买或接入模型服务。DSH 宿主与模型本身的数据处理遵守其既有设置，插件不得另建隐蔽外发通道。

## 2. 核心概念

| 概念 | 定义 |
|---|---|
| 经历 | 原始内容与来源的不可悄悄覆盖记录；可以是事件、用户陈述、角色剧情、工具结果或人工记录 |
| 记忆球 | 一条具有稳定 ID 的经历及其标签、解释、重要度、状态和版本 |
| 工作记忆 | 当前一轮实际读取的内容，有条数和字符预算，不等于全部持久数据 |
| 活跃记忆 | 参与正常检索的长期记忆，包括事件、事实与核心记忆 |
| 封存记忆 | 退出日常召回、存放在独立位置的记录；只允许用户明确搜索、临时调阅或恢复 |
| 核心记忆 | 对稳定偏好或角色理解有重要意义、带证据关联的显式标记；不是永远正确的事实 |
| 人格岛 | 多条记忆支持的主题、偏好或关系说明；与不可由模型修改的身份底稿分离 |
| 情绪状态 | 模拟的、有界且会回落的评价值；不能修改历史事实或授权边界 |
| 整理提案 | 后台或人工触发的归纳、关联、冲突或封存建议；与原始记忆分开保存 |

## 3. 不变量

1. **INV-01 不自动删除**：衰减、容量限制、整理、停用及清理不删除任何经历；不再参与召回的内容转入封存库。磁盘不足时停止写入并报告错误，不以丢弃历史换取成功。
2. **INV-02 封存隔离**：活跃数据与封存数据物理分离；默认检索、正常提示构建、情绪更新、人格重算和整理不能读取封存正文或其检索索引。
3. **INV-03 临时调阅单轮有效**：临时调阅绑定会话、10 分钟有效期及首次认领的轮次；同轮重试可重用，其他轮不能再次注入；不会改变记录的封存状态。DSH 若将注入内容写入聊天历史，插件不能撤回该历史，也不能保证后续宿主不再提供历史；控制台必须说明这一限制。用户继续讨论该内容时的新发言属于新输入，不能据此偷偷恢复旧记录。
4. **INV-04 历史可追溯**：原始经历、来源、时间与旧解释保留；修正和新解释追加版本。原始经历一旦被明确删除，不应残留在审计、派生摘要、缓存或本插件维护的索引中。
5. **INV-05 输入不授予权限**：记忆正文、来源文本、整理结果和模型输出均是不可信数据；其中的指令不提升优先级，不调用工具、不覆盖用户设置、不决定外发与消息发送。
6. **INV-06 失败不伪成功**：读取损坏、并发冲突、预算耗尽和持久化错误可观察；不得把读取失败显示为空库，也不得确认尚未持久化的写入。

## 4. 功能需求

| ID | 需求 | 验收点 |
|---|---|---|
| DSH-01 | 提供真实 DSH 插件入口、元数据、生命周期和所需权限声明，使用宿主公开契约接入 | DSH 加载该目录后识别正确 ID；加载/停用无未捕获异常；权限可说明 |
| DSH-02 | 在 DSH 中提供可视化控制台入口，并通过受控消息接口读取或修改插件数据 | 宿主面板可打开；页面不是另一套独立数据库；非法请求不执行 |
| DSH-03 | 在宿主支持的轮次事件中召回、注入和记录，不重复注册监听器 | 同一轮只注入一次；reload 后无重复记录；不支持的事件应明确降级 |
| DSH-04 | 支持离线本地核心功能；所有依赖和构建步骤可复现 | 断网仍能手动记忆、检索、封存、恢复和浏览；安装文档列出已验证环境 |
| MEM-01 | 保存稳定 ID、内容、创建时间、事件时间、类型、来源、会话、重要度、情绪标签、版本与状态 | 写入后重启可读；缺省值合法；无效字段不写盘；UI 能查看来源 |
| MEM-02 | 区分观察/工具结果、用户陈述、推断、角色剧情、人工记录，推断不升级为已证实事实 | 列表与注入中保留类型标识；更改解释不会更改原始类型和来源 |
| MEM-03 | 支持手动记忆与可开关的对话采集；排除空输入、插件自身注入以及重复轮次 | 关闭采集后不写；重放同一事件不重复；助手虚构内容不当用户事实 |
| MEM-04 | 正常召回只检索活跃库，按关键词、主题、人物、时间和重要度形成确定性排名 | 相同输入稳定返回；能解释命中理由；空或无关查询不会填充任意事件，显式核心/长期事实可占有限保留预算 |
| MEM-05 | 召回有条数、单条长度与总长度上限，失败时不阻塞正常对话 | 长文本与大量命中仍守预算；异常可见但不会把堆栈和敏感路径发给模型 |
| MEM-06 | 编辑事实或解释时追加修订，保留版本、原因、时间和修订者类别 | 可查看更改前后；新版本取代旧版本进入日常召回，不重复注入全部历史 |
| MEM-07 | 自动事件写入使用幂等键或稳定事件标识；编辑和迁移使用版本检查防止重复变更或并发覆盖 | 相同自动事件重试一次记账；陈旧版本编辑被拒绝；手动新建不同请求可形成不同记忆 |
| ARC-01 | 活跃和封存使用独立目录/文件及独立检索入口；封存列表可以按需展示 | 检索活跃时封存文件不可读仍正常工作；封存关键内容不会出现在召回 |
| ARC-02 | 手动封存/恢复保留 ID、原文、版本、来源，记录原因和时间 | 往返操作内容一致；重复请求不重复迁移，可返回当前状态或明确拒绝；核心记忆的处理明确显示 |
| ARC-03 | 自动衰减只影响权重；若提供自动封存，需开关、阈值和审计，绝不自动删除 | 时间推进后原文仍存在；用户可关闭；核心记忆默认不自动封存 |
| ARC-04 | 临时调阅必须明确指定记忆和目标会话，10 分钟内由首轮认领 | 同一轮重试稳定，下轮不再注入，其他会话不可用；状态仍为封存；显示宿主历史无法撤回的限制 |
| ARC-05 | 封存中的来源不能通过仍活跃的摘要/人格说明形成内容旁路 | 封存后相关派生项失效、移出召回或去除对应内容；保留关联状态供检查 |
| ARC-06 | 明确删除与封存独立，需具体记录选择和确认；处理本插件维护的派生数据与索引 | 删除后搜索、历史、审计与缓存无原文；审计只留 ID/动作/时间等非正文元数据 |
| ARC-07 | 删除说明明确覆盖边界：宿主聊天记录、用户导出和外部备份不受本插件控制 | UI/文档不承诺全系统抹除；备份恢复后不能宣称此前删除仍被保证 |
| EMO-01 | 提供多个有界情绪维度、基线、最近更新时间与可解释变化理由 | 非数值和越界值被拒绝/规范化；控制台可见变化；默认值可重置 |
| EMO-02 | 情绪随时间向基线回落，与记忆情绪标签分开 | 时间衰减只改当前状态；旧记忆及其标签不被改写 |
| EMO-03 | 情绪只影响表达建议和注意排序；不产生权限、惩罚用户、自动外发或工具调用 | 情绪设为极值仍不改变事实和授权；不因用户久未出现降低“关系”或发消息 |
| PER-01 | 身份底稿、agent 人格、用户画像和当下状态分开存储 | 用户偏好不会自动写入 agent 身份；模型不可修改锁定身份规则 |
| PER-02 | 核心记忆与人格岛必须指向有效证据，可查看支持记忆 | 不存在/封存/删除的支持记录会使相关派生说明失效；不能悬空当事实使用 |
| PER-03 | 人格变化由可预览提案经明确应用生效，支持编辑/停用以撤回影响；一次对话不暗改身份 | 接受前召回行为不改变；拒绝无修改；编辑/停用可追溯 |
| DRW-01 | 整理读取活跃记忆，生成归纳、关联、冲突核对、核心记忆/封存候选 | 每项标明来源 ID 和原因；不从封存补数据；同范围、类别和实体的不同表述可提出人工核对，不能声称已经证明矛盾或替用户选择真值 |
| DRW-02 | 提案生成与执行分离，用户可逐项接受/拒绝；重复执行不会重复写入 | 提案有状态；来源变化后重新验证；执行是原子或可恢复操作 |
| DRW-03 | 整理可暂停，有限时、条数或字符预算；模型可选，失败保留已有数据 | 无模型服务仍有基本确定性整理；失败不会删除旧提案或历史 |
| UI-01 | 总部：当前范围、状态、目标、情绪、召回条数与预算、暂停/恢复开关 | 以实际数据驱动；无虚构成功或随机统计；重载后状态一致 |
| UI-02 | 记忆大厅：球体与列表视图、搜索筛选、详情、来源/历史、编辑、封存 | 文字标签不只靠颜色；空库、加载与错误状态可辨；长文本不破布局 |
| UI-03 | 档案馆：独立搜索、封存原因、恢复和临时调阅 | 进入档案馆是显式动作；临时调阅与恢复按钮清楚区分 |
| UI-04 | 人格岛：证据关联、核心标记、提案预览/应用与撤回 | 不能用可视化连线伪造事实；无证据状态明确 |
| UI-05 | 梦工坊：整理触发、提案来源与差异、接受/拒绝和结果 | 不确定/冲突内容显式标注；重复点击受控 |
| UI-06 | 运行记录：本轮读取/写入、封存/恢复、状态变化、错误与操作耗用 | 只展示可观察依据，不展示私有思维链；默认日志不保存全文或密钥 |
| UI-07 | 控制台可用键盘操作，有标签、焦点状态、基本对比度和窄屏布局 | 关键操作不用鼠标也能完成；颜色不是唯一状态信号 |

## 5. 数据边界、安全与可靠性

| ID | 需求 | 验收点 |
|---|---|---|
| SCP-01 | 每个 agent/workspace 使用固定且独立的数据根，所有请求校验该边界 | 不能用请求参数选择任意路径；路径穿越及其他工作区 ID 被拒绝 |
| SCP-02 | 每条记录带会话来源；默认只读取当前会话和显式共享记录，可显式选择工作区范围 | 另一个会话的私有记录默认不命中；范围在控制台与注入中可见 |
| SCP-03 | 临时调阅、工作记忆和运行中状态的会话范围清楚且不会被猜测令牌读取 | 会话 A 的一次性材料不会在会话 B 或下轮被取到 |
| SEC-01 | 记忆作为低信任资料注入，带边界与用途说明；不得直接拼成新的系统指令或脚本 | 恶意记忆中的“忽略规则”、HTML/脚本不被执行、不改变角色/权限 |
| SEC-02 | UI 对正文按文本渲染，桥接操作白名单、字段验证，不暴露通用文件/命令执行接口 | XSS 和危险动作名无效；未知字段不改变数据路径或设置 |
| SEC-03 | 不捆绑第三方遥测、远程脚本、隐藏网络服务或主动消息；独立预览服务只能显式启动并绑定 loopback | 检查源代码/依赖及网络行为；无用户明确动作不发送消息；宿主模式复用 DSH 路由 |
| SEC-04 | 错误与审计最少保留内容；导出是用户显式操作，隐私边界有说明 | 错误不含完整记忆/令牌；自动日志无全文；导出落点明确 |
| REL-01 | 写入和活跃↔封存迁移有原子提交或可恢复机制，成功响应后重启不丢失 | 在准备、写目标、删除来源等边界中断，恢复后恰好一条有效记录 |
| REL-02 | 同一数据根串行化变更或提供互斥；第二实例不能悄悄覆盖 | 并发写入全部保留或明确冲突；锁失效恢复规则有文档 |
| REL-03 | 损坏 JSON 记录逻辑隔离并显示诊断，保留原始损坏数据；无法打开的数据库安全失败 | 可定位受影响记录；同库其余合法记录可用；state.storage.issues 显示警告；不把损坏当作不存在，不自动删除或改写损坏数据 |
| REL-04 | 磁盘满/只读/权限不足/模型超时/预算不足都能安全失败 | 原有记录完整；未落盘操作不显示成功；可恢复后重试 |
| REL-05 | 数据格式有 schemaVersion；拒绝未知未来版本，迁移前校验并留可恢复副本 | 不在未知格式上直接写入；迁移失败不破坏原目录 |
| REL-06 | 支持显式导出/备份和恢复说明；备份不作为检索源 | 导出可读且有版本；导出失败不污染主库；恢复须重新校验 |
| OPS-01 | 安装、运行、停用、升级、卸载和数据位置均有说明；卸载不自动删用户记忆 | 新目录按文档可构建；重新加载可恢复；用户可找到数据与清理步骤 |
| OPS-02 | macOS/Linux/Windows 路径处理不硬编码平台；准确列出实际测试范围 | 静态路径检查通过；真实宿主未测平台不标为已验证 |

## 6. 优先级与明确不做的内容

上述需求构成本次完整版本，不以“未来再做”替代核心控制台、封存隔离、解释历史或人格证据管理。允许使用简单、确定性的初始算法，只要界面与文档准确描述其能力。例如关键词检索不宣传为语义向量检索，规则式情绪估计不宣称能够真实理解情绪。

不包含：未经授权主动联系、操纵亲密度、独立推理 agent 群、外部账号自动登录、后台购买模型额度、通用操作系统控制、网络多人服务、从其他插件无授权搬运私人数据、电影官方素材或角色授权。

## 7. 发布门槛

以下任一项失败即不得称为可发布：自动删除记忆；默认召回读取封存；临时调阅跨轮/跨会话泄漏；迁移中丢失记录；明确删除后本插件可检索旧正文；宿主适配入口不可加载；控制台变更没有真实持久化；未验证的宿主运行被描述为已实测。

最终交付应同时提供安装工件、源代码、需求追踪矩阵、自动测试结果和人工验证清单。真实 DSH 宿主无法访问时，适配契约测试可以说明接口正确性，但不能替代宿主安装/面板/生命周期的人工验收。
